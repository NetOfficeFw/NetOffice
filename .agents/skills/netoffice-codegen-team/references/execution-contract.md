# NetOffice Code Generator Execution Contract

This is the detailed execution contract for [the team](../../../teams/netoffice-codegen-team.md). Issue #509 and its decisions D1-D11 remain authoritative if wording here conflicts.

## Frozen inputs and output profile

The lead records exact commits for NetOffice, the v0.8 Data input, the accepted Data v2 output, and MicrosoftDocs/VBA-Docs. Reports also pin generator source, policy, Roslyn/package lock, schemas, and docs digest.

Generated output is C# 7.3, nullable-disabled, invariant-culture, CRLF, UTF-8 BOM, and final-newline. Every managed file eventually has one stable ownership marker naming the generator and output-format schema; never emit `<auto-generated>`.

## Data v2 gate

The sequence is mandatory:

1. Freeze the v0.8 input SHA.
2. Accept the generator-owned v2 schema with canonical serialization, provenance/source locations, and explicit unknown/ambiguity records.
3. Convert the complete corpus; resolve stable IDs, aliases/unifications, accessors, signatures, and observation sets.
4. Run the temporary converter from two clean v0.8 worktrees; Verification repeats it from a third.
5. Record converter/schema SHAs, exact commands, ambiguity-report hashes, and complete output-tree hashes in signed migration evidence.
6. Obtain maintainer resolutions for every ambiguity.
7. Merge and freeze the Data v2 SHA, then remove converter source. Production generation never reads v0.8.

Typelib and Emission may develop against accepted schema fixtures. Projection, Documentation binding, CLI composition, and vertical slices require the merged Data v2 SHA.

## Component contracts

### Parity

Extract a versioned Wrapper Contract from the frozen current source: public/protected API, attributes/defaults/interface maps, invocation operation/name/argument order/modifiers/return conversion, version support, event names, enumerator strategy, docs baseline, and current file/type partition. Classify every file/type part as generated, companion, obsolete, or unresolved. Any unresolved classification blocks ownership cutover.

### Typelib

`import-typelib` uses `LoadTypeLibEx(REGKIND_NONE)` on explicit files, traverses dependencies, fully decodes TYPEDESC/PARAMDESC/VARDESC, releases paired descriptors, and rejects unresolved references. A raw observation identity includes typelib GUID/major/minor/LCID/SYSKIND, binary/dependency hashes, Office build/channel/architecture/SKU/locale, TYPEATTR GUID/kind, MEMID/INVOKEKIND, canonical typed signature, and parameter ordinal.

`merge` is append-only for observations. One valid observation may add an entity; missing entities produce removal candidates; conflicting signatures remain parallel until reconciled; removal requires an approved override. SupportByVersion remains monotonic by major Office version.

### Projection

Each output facet has one typed stage owner. Stages cover identity resolution, inheritance/duplicates, naming/signatures, overloads/version support, invocation plans, enumerator/indexer/event/collection capabilities, docs binding, and file partition. Overrides carry logical ID, facet, expected match count, rationale, provenance, and compatibility status; stale or multi-match overrides fail. `explain <id>` traces each emitted facet to raw facts, stages, and overrides.

### Documentation

`docs sync` is the only networked docs step. It pins VBA-Docs, indexes every `api_name`, article kind, source path, and existing reference metadata, then writes a committed mapping ledger with exact, approved-alias, manual, unmatched, or ambiguous status. Ambiguous records never attach automatically.

Constrained Markdown becomes structured XML-doc AST. Emit summaries, params, returns, remarks, notes, enum tables, examples as `<code>`, and canonical per-member Learn links. Emit `<param>` only for real generated parameter names. DAO/ADODB/VBIDE and unmatched members receive synthesized fallback docs. Record source/XML-doc/package size deltas. `THIRD-PARTY-NOTICES.md` must identify Microsoft, VBA-Docs and its pinned commit, CC BY 4.0, disclaimer, and modification statement; every affected package includes it.

### Emission and storage

Projection and docs produce canonical `WrapperFile` IR. Build one complete `CompilationUnitSyntax`, attach structured doc trivia, format once, reparse with `LanguageVersion.CSharp7_3`, reject diagnostics, encode the required bytes, and release syntax trees after use. The cache is content-addressed by IR hash and is never correctness state.

A run key covers Data/docs tree IDs, schemas, generator source, policy, Roslyn/package lock, output profile, and docs digest. Unchanged key is a no-op; otherwise recompute the complete model and projection, then format/write only changed IR. Cacheless full output must equal incremental output byte-for-byte.

The write plan stages and validates paths, types, syntax, and hashes before locking. Changed writes are atomic. Deletion is permitted only in allowlisted `Source/<Api>/Generated/` roots when the marker exists and current hash equals the previous manifest. Commit the manifest last; a mismatch aborts without mutation.

### CLI

The command surface is:

- `import-typelib`
- `merge`
- `docs sync`
- `generate [--locked] [--check]`
- `verify`
- `diff`
- `explain <id>`
- `bootstrap-ownership --locked (--check|--apply)`

`generate --locked`, `verify`, `diff`, and `explain` are offline and Office-independent. Exit codes are 0 success/clean, 1 usage-validation-generation failure, 2 drift found by `generate --check`, and 130 cancellation. `--check` changes no source bytes/timestamps, manifest, or cache.

## Slice integration DAG

For each slice, in fixed order:

1. Merge the Parity contract/classification artifact.
2. Projection and Documentation submit independent changes pinned to that artifact and Data v2 SHA; before cutover Documentation uses `baseline` only.
3. Emission produces a dry-run byte/diff artifact pinned to accepted inputs.
4. CLI composes accepted producer versions without bypassing validators.
5. Verification independently reproduces the slice and records pins, profile, command, hashes, and differences.
6. The lead integrates only at zero unexplained contract differences. Intentional differences require an approved compatibility-ledger record first.

## Ownership cutover

After all twelve API projects have zero unexplained contract differences:

1. Produce accepted marker-bearing `baseline` output.
2. Remove exactly one expected marker line per file and commit the dedicated formatting result; record marker-bearing and marker-stripped tree hashes and rerun contract/build checks.
3. Commit a path-only move of marker-stripped bytes into `Source/<Api>/Generated/`; add formatting and move commits to `.git-blame-ignore-revs`.
4. `bootstrap-ownership --locked --check` verifies no manifest, allowlisted destinations, exactly one marker in staged output, and marker-stripped equality to the frozen baseline; it writes nothing.
5. `--apply` performs no deletes, transactionally installs the complete marker-bearing tree, reparses/builds it, and commits the initial manifest last. Failure restores the complete marker-stripped tree/no manifest. Bootstrap refuses once a manifest exists.
6. Only later normal runs may replace or delete marker/hash-verified files.

After cutover: import the first maintainer-supplied Current Channel snapshot; enable the pinned `vba` profile in reviewed product batches; then implement #506 runtime capability and generator rules, #508 analyzer/conformance, and #507 managed/real-COM tests.

## Verification gates

Run from the repository root on Windows unless the gate says otherwise.

1. Restore/build/test `Tools/CodeGen/NetOffice.CodeGen.sln` with .NET 10 and locked packages.
2. Validate the merged Data v2 SHA/schema, signed conversion evidence, resolved ambiguities, references, and complete tree hash.
3. Generate DAO cachelessly with `baseline`; require zero unexplained Wrapper Contract differences and valid output bytes/C# 7.3.
4. Compare two cacheless full runs and cacheless versus incremental. From one warm state, separately mutate one logical data member and one typed policy record with expected match count one. Require dependency-derived file sets from `explain`; enforce 30 s/3 s/5 s and 2 GB budgets.
5. Exercise clean/drift/error/cancellation CLI exits and prove `--check` is side-effect-free.
6. Fault-inject every bootstrap/write boundary. Require old-valid or complete-new tree/manifest and no out-of-root changes.
7. Verify all twelve projects, then build `Source/NetOffice.sln -c Release` and run non-integration tests.
8. Scan the complete VBA-doc output and packages: approved mappings or fallback for every public generated member, valid params/links/content, no ambiguous attachment, deterministic digest, size reports, and exact notice/package ledger agreement.
9. On provisioned Office machines, verify Current Channel provenance and #507 exact COM-call/proxy/lifetime assertions.

Verification never edits producer fixtures, expected contracts, or generated output. It reports the first divergent owner with the smallest reproducible fixture.
