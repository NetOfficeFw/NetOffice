# NetOffice Code Generator Team

Use this skill for work governed by [NetOffice issue #509](https://github.com/NetOfficeFw/NetOffice/issues/509).

Before editing:

1. Read the [team definition](../../teams/netoffice-codegen-team.md).
2. Select exactly one role from `.agents/agents/` and obey its sole-writer boundary.
3. Read the relevant sections of [the execution contract](references/execution-contract.md).
4. Confirm the task names all frozen input commits, accepted schema/artifact versions, and upstream reports it consumes.
5. Return shared-path or cross-role changes to `netoffice-codegen-lead`; do not edit another role's files.

## Binding decisions

Issue #509 decisions D1-D11 are binding:

- Implement an independent MIT-licensed generator. The obsolete Ms-PL generator is behavioral evidence only; never copy its code, templates, or resources.
- Treat current checked-in `Source/<Api>/` wrappers at the frozen commit as the compatibility oracle.
- Emit C# 7.3 with nullable disabled, invariant culture, CRLF, UTF-8 BOM, and a final newline.
- Read only Data v2 in production. The v0.8 converter is temporary and removed after independently reproduced migration evidence.
- Acquire new type libraries from Microsoft 365 Current Channel; absence produces a removal candidate, never an automatic deletion.
- Apply full pinned English VBA documentation only after baseline parity and ownership cutover, with CC BY 4.0 attribution in every affected package.
- Generate under `Source/<Api>/Generated/` only after all projects reach zero unexplained contract differences.
- Use a stable ownership marker without `<auto-generated>` and transactional marker/hash-verified writes.
- Meet the issue budgets: full generation at most 30 seconds, no-op at most 3 seconds, one-member data or rule change at most 5 seconds, and peak managed memory at most 2 GB on the 32-logical-core baseline.

## Collaboration rules

- One writer per path. Cross-owner work is split into producer contract/API, consumer update, then lead-owned integration wiring.
- At most four producer streams run concurrently: Typelib, Projection, Documentation, and Emission.
- The fixed vertical-slice order is DAO; Excel Range/WorksheetFunction; PowerPoint events/collections; Outlook/Access event conflicts; ADODB duplicates/inheritance; Office Adjustments.
- Pre-cutover runs use the `baseline` docs profile and reproduce current comments. Post-cutover documentation batches use the pinned `vba` profile.
- Route a failure to the first divergent stage: raw/logical data to Data v2 or Typelib; projected facets to Projection; mappings/docs AST to Documentation; syntax/bytes/write plans to Emission; command/pin/exit behavior to CLI.
- Never patch generated files or weaken Verification expectations. Change an expected contract only through an approved Parity/compatibility-ledger update.

## Human-only approvals

Agents may report but never invent:

- Data conversion ambiguities and stable-identity resolutions.
- Documentation aliases, manual mappings, and ambiguities.
- Removal overrides and compatibility classifications.
- Microsoft 365 Current Channel acquisition evidence.
- Frozen Data/VBA-Docs commits and CC BY package attribution.

Continue all independent records while reporting blocked records explicitly.

## Required handoff

Every role finishes with:

- **Result**: completed behavior or exact blocker.
- **Owned files**: files changed inside the role's boundary.
- **Input pins**: NetOffice, Data v2, VBA-Docs, contract, policy, and package-lock identities used.
- **Artifacts**: schema versions, report paths, logical IDs, hashes, and expected/actual file sets.
- **Verification**: exact commands and observed results only.
- **Handoffs**: next owner and the accepted artifact it must consume.
- **Blockers**: records requiring maintainer approval; never a blanket block when independent work remains.
